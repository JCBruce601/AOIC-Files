Start Here: The Program in Two Minutes

Tyler Technologies partners with the Administrative Office of the Illinois Courts (AOIC) to build a statewide court analytics program covering all 102 Illinois counties. County clerks, and in most cases the third-party case management system (CMS) vendors they rely on, submit case-level data to the Alliance Exchange Pipeline (AEP). The AEP is an API endpoint that checks every record against a published JSON contract before anything is stored. Accepted records are stored, combined across vendors, and published nightly to the AOIC Enterprise Data Platform (EDP) in Tyler's CJIS-compliant cloud. From there they power the analytics applications that judges, court administrators, clerks, probation staff, and AOIC leadership use.

The contract is Exhibit 4A to Agreement 22SPF11, originally effective August 1, 2021 and amended June 4, 2025. The Second Amendment, executed with a sign date of April 28, 2026, reset the delivery schedule, added Problem Solving Courts terms, and extended the term into 2027. Two of its clauses come up often: Tyler must notify the AOIC within three days of receiving first data from a new source, and the AOIC must have access to every staging application. As of August, the platform held about 1.32 million records across five program areas.

The Core Challenge Has Shifted

In February the hard part was getting vendors to transmit consistently. That is still true, but the harder part now is proof. The AOIC is under public scrutiny over access to pretrial data, and it has asked Tyler for evidence that every dashboard is built, populated, and matches its requirements. Expect requests to arrive with urgency, and answer them with data, screenshots, and dates rather than assurances.

How Decisions Get Made

A Supreme Court task force led by Justice Eugene Doherty of the Illinois Appellate Court, Fourth District, sets strategic direction. The AOIC runs the program day to day through John Chatz and Skip Robertson. Direction flows from the task force to the AOIC, and from the AOIC to Tyler. The AOIC prefers to send communications to CMS vendors itself, so Tyler drafts and the AOIC delivers.

How the Data Flows

Every workstream except eFile follows the same five steps. eFile Analytics draws from Tyler's own eFileIL filing data instead of CMS vendor submissions.

  1. Step 1County and vendor

    A clerk's CMS vendor, or a county submitting for itself, exports records and builds a JSON envelope.

  2. Step 2Alliance Exchange Pipeline

    The vendor authenticates and sends the envelope. The AEP checks it against the entity and event contracts.

  3. Step 3Storage

    Accepted records are backed up and merged into one row per record ID, one table per dataset.

  4. Step 4Data platform

    A scheduled job publishes the tables to the AOIC Enterprise Data Platform. eFile is moving to the Tyler Data Store.

  5. Step 5Applications

    Analytics applications on the CJIS cloud read the datasets, with access set by role and jurisdiction.

Rules That Answer Most Vendor Questions

Two contracts decide acceptance

The entity contract defines the fields and allowed values for a dataset. The event contract defines which vendor may submit which workstream for which county. A record can be well-formed and still be refused because the vendor is not mapped to that county.

Updates reuse the record ID

There is no update event. A vendor corrects a record by sending a new-record event with the same record ID. Omitted fields keep their value. A field sent explicitly as null is cleared.

Always validate synchronously

Vendors should set synchronous validation to true. Without it, an invalid record still returns success and the errors arrive only by email, which vendors often never see.

Staging is stricter than production

Staging enforces allowed values and patterns. Production does not, by design. Vendors prove quality in staging, never in the development environment.

Values are case-sensitive

Vendor names and county names must match the contract exactly. "cFive" fails where the contract says "Cfive," and "Dupage" fails where it says "DuPage."

Releases run on a schedule

Contract changes ship through the Alliance team every other Thursday afternoon. Opening the pull request deploys to development immediately, and closing it does not undo that.

The full technical reference, including envelope anatomy, error triage, and environment details, lives in the AOIC knowledge base on SharePoint. See Where Things Live.

Four Habits That Keep You Out of Trouble

  • Never release anything to vendors without the AOIC's explicit written go-ahead. The March 12 revert is the reason.
  • Answer AOIC concerns with evidence: side-by-side numbers, screenshots, and record counts.
  • Let the AOIC send vendor communications. Tyler drafts, the AOIC delivers.
  • Tell the AOIC within three days when data first arrives from a new source. The Second Amendment requires it.

Glossary

AOIC
Administrative Office of the Illinois Courts, the client.
AEP
Alliance Exchange Pipeline, the API endpoint where vendors submit records and where every record is validated.
ACB
Alliance Community Builder, the internal admin tool for setting up vendor systems and credentials. Vendors never see it.
EDP
Enterprise Data Platform, the AOIC's data platform at aoic.cjis.socrata.com.
TDS
Tyler Data Store, the newer storage backend that eFile Analytics is moving to.
CMS
Case management system, the software courts and probation departments use to manage cases.
CJIS
Criminal Justice Information Services, the FBI security standard. All AOIC applications run in Tyler's CJIS-compliant cloud.
Courts Pretrial
The current pretrial workstream, sourced from court CMS data, with two datasets.
PSC
Problem Solving Courts, such as drug, mental health, and veterans courts.
OSPS
Office of Statewide Pretrial Services.
NCIC code
The county identifier used in pretrial and court datasets, for example IL016025J.
Entity contract
The JSON rules for one dataset: its fields, types, and allowed values.
Event contract
The JSON rules for which vendor may submit which workstream for which county.
Record ID
The key for a record within a dataset. Resending it updates the record.
Compass Check
The biweekly client meeting run by Courts & Justice.
Kiteworks
The secure file transfer tool used for credentials and sensitive reports.
SoQL
Socrata Query Language, the SQL-like language behind dashboard metrics.
WCAG
Web Content Accessibility Guidelines. The contract requires version 2.1 AA.
